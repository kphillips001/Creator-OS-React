TRANSPORT STRATEGY REVIEW

PURPOSE

Previous architecture recommendations assumed a future
multi-creator SaaS platform.

This assumption is incorrect.

The migration target is a single creator system.

The purpose of this task is to re-evaluate the transport architecture
under the correct business requirements.

--------------------------------------------------
ACTUAL BUSINESS REQUIREMENTS
--------------------------------------------------

This project supports:

- Ava Blackthorne
- One Telegram account
- One AI creator persona
- One Fanvue account
- One owner/operator

The goal is:

Social Traffic
    ↓
Telegram Conversation
    ↓
FanvueChatbot Brain
    ↓
Fanvue Media Links
    ↓
Purchases

--------------------------------------------------
NON-REQUIREMENTS
--------------------------------------------------

The system does NOT require:

- Multi-creator support
- Multi-tenant architecture
- Creator registry
- Bot-per-creator architecture
- Agency support
- SaaS scalability

These should not influence recommendations.

--------------------------------------------------
TASKS
--------------------------------------------------

1. Re-evaluate User Session vs Bot Token.

2. Determine which architecture best matches:

- creator realism
- relationship building
- conversational continuity
- Telegram DM experience
- Fanvue Media Link sales

3. Compare:

A) Telethon User Session

B) Telegram Bot Token

under the actual requirements.

4. Estimate migration effort for both.

5. Determine which option best reuses:

- existing Telegram repository
- existing FanvueChatbot brain

6. Determine which option minimizes migration risk.
